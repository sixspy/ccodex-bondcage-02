# 拆笼分拨纪要（当日锁死）

- 产品：保证金笼（bondcage）
- 纪要日：2026-11-22
- 状态：**当日锁死**（本纪要落库后不得改选路径；后续变更须另立纪要并整笔回退）
- 适用库：`data/app.db`（库文件不换路径）
- 适用页面：拆笼页、入笼页、对账页、账户页、审计页（五页账实同源）

## 一、事故口径

拆笼页提交后只看到“拆分作业”，没有子份额；原笼可用额原封不动；对账仍显示整笼平衡。
根因是 `split_svc` 为空桩：只登记 `split_jobs` 与审计，不切分笼面。

该现象称为**拆后单笼假绿**：表面上对账平衡，实际可用额没有切成两笔可独立处置的份额。
任何只改拆笼按钮文案、只改角标、或只登记作业而不产生子笼的实现，均不算通过。

## 二、锁定方案（二选一，已选甲路）

**甲路：整笔切分同事务落库（本纪要锁定）**

1. 同一提交内，按左、右金额扣减原笼 `available`，原笼状态置为“已拆分”。
2. 同一提交内新建两只子笼，分别承接左、右金额；子笼为独立笼面，可各自核验、解笼、罚没。
3. 同一提交内写拆分关系（`split_links`）、拆分作业、审计（父笼一条、子笼各一条）。
4. 任一步失败：原笼可用额、原笼状态、两只新建子笼、拆分关系、拆分作业、审计**一并回滚**。
5. 成功提交后：原笼可用额下降，两只子份额可按笼编码查询并独立处置。

**乙路（影子子笼草稿再原子晋升）本纪要明确不采用。**
禁止在甲路实现中夹带影子草稿、晋升标记或双写；禁止两条路径混用。
请求若声明走影子子笼，一律记为**拆笼偏航**并拒写（见第四节）。

## 三、并发与争用

- 拆同一只笼必须争抢 `cage:{cage_id}` 笼锁。
- 后到者不写任何业务数据，只落一条争用痕（`contention_log`），返回 409。
- 已拆分的笼再次提交拆笼，同样视为争用，只留争用痕。
- 原笼状态更新使用带条件的比较并交换（`status='已冻结' AND available=?`），防止两笔拆笼同时落地。

## 四、偏离纪要

- 任何非“整笔切分”的 `mode`（含“影子子笼”）均记审计动作 `split_deviation`（拆笼偏航），载荷记录请求模式、锁定模式、纪要编号，并拒写。
- 拒写后原笼、子笼、拆分关系、拆分作业均不得变化。

## 五、五页同源

| 页面 | 同源要求 |
|------|----------|
| 拆笼页 | 显示原笼扣减后的可用额、两只子笼编码与金额、拆分作业状态 |
| 入笼页 | 笼卡片/详情可查父子关系，子笼可继续核验与处置 |
| 对账页 | 原笼口径为 `可用 + 已拨付 + 已罚没 + 已拆出 = 笼总额`；子笼各自平衡 |
| 账户页 | 账户冻结额仍等于全部活笼可用额合计（父子合计不变） |
| 审计页 | 可见 `cage_split`、`cage_split_child`、`split_deviation` 与争用痕 |
